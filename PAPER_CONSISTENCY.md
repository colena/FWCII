# Consistency of the paper, code, and numerical results

Checked on 12 September 2026 against the bundled [paper](fractional_wiener_chaos_II_FINAL.pdf), *Fractional Wiener chaos: Part 2. Interface spectral chaos and decay of collective correlations*, by Elena Boguslavskaya and Elina Shishkina.

**Outcome: no numerical inconsistency was found in the checked application.** The printed inputs and numerical values in Section 6.4 agree with the stored reference and a fresh execution. The plotted normalization and the implemented covariance, amplitude, and truncation formulas agree with the paper. This is a numerical reproducibility check of the threshold application, not a verification of every theorem in the paper.

## Sources and method

- Paper: the 23-page `fractional_wiener_chaos_II_FINAL.pdf` supplied in this repository. Section 6 spans pages 17-20; Figure 1 is on page 21. Page references here refer to the page numbers printed in the PDF.
- Original output: [`reference/results.json`](reference/results.json), which is byte-identical to the original companion's `results.json` used for this check.
- Fresh output: `outputs/results.json` and `outputs/results.txt`, generated by `python reproduce.py`. These generated files are ignored by Git and can be recreated locally.
- Implementation: [`reproduce.py`](reproduce.py) and [`interface_modes.py`](interface_modes.py).

The PDF text and the complete relevant rendered pages were inspected. The numerical example and Figure 1 were compared with a fresh run. The output comparison traversed every JSON field, excluding the `versions` object, checking structure and nonnumeric values exactly and numeric values with relative tolerance `1e-8` and absolute tolerance `1e-11`.

Paper SHA-256: `4b8768a25ce65acc92dae04fe9b577c1151bbe7ef576cfac1c3d564b7a2ef9aa`.

## Covariances versus plotted correlations

The JSON benchmark is not directly the vertical coordinate of Figure 1. At `mu = 1`, `p_mu = 1/2`, so dividing by `[p_mu*(1-p_mu)]^2` multiplies a covariance by 16. The curves are finite 32-mode sums; the round markers are independent Gaussian quadrature benchmarks.

For example, the fresh run at `t = 1` gives:

| Quantity | Shared clock | Independent clocks |
| --- | --- | --- |
| Gaussian quadrature covariance | `0.0150734676645318` | `0.0125986424003652` |
| 32-mode covariance | `0.0149569488191681` | `0.0125392875116382` |
| Normalized quadrature marker | `0.241175482633` | `0.201578278406` |
| Normalized 32-mode curve | `0.239311181107` | `0.200628600186` |

For `mu = 1/2`, the normalization divisor is approximately `0.0446862244726752`, giving `t = 1` curve values approximately `0.174136402231` and `0.130458951540`. These agree visually with the deformed panel. The figure check covered the visible curves, markers, axes, and normalization; the paper's vector plot was not independently digitized into a separate data series.

## Fresh-run agreement and limitations

- All **499 numeric fields** outside version metadata passed the recursive comparison. The largest absolute difference was approximately **`9.84e-13`**, in the 21st retained coefficient for `mu = 1/2` (`spectral[1].coefficients[20]`).
- Array sizes, keys, and the three nonnumeric leaf values outside version metadata agreed exactly. Both runs recorded zero quadrature warnings.
- The reference used Python 3.12.13; the fresh run used Python 3.12.14. NumPy 2.3.5, SciPy 1.17.0, and Matplotlib 3.10.8 agree. These small numerical differences do not affect any printed paper value.
- At `t = 1,000,000`, scaled shared covariances differ from their finite-sum amplitudes by at most about `4.02e-7` relatively; scaled independent covariances differ by at most about `3.71e-6`. These finite-time differences are consistent with approach to the limits in equation (22), not discrepancies.
- Finite-mode amplitudes are partial sums, not the exact infinite-series constants. Their omitted contributions have separately reported remainder estimates.
- The bands and bounds cover spectral truncation using floating-point inputs. They do not certify root completeness, special-function evaluation, or quadrature uncertainty, as the paper also states.

## Repeat the check

From the repository root in the environment described in the README:

```sh
python reproduce.py
python -m unittest -v test_reproduce
```

The eleven tests include `test_paper_section_6_4`, which checks both stored and fresh results against the four values transcribed from the PDF and its stated parameters, and `test_full_reference_consistency`, which compares the complete reference and fresh JSON outputs. The PDF itself is not parsed during the tests, so readers need no additional PDF dependencies. If a revised paper changes its parameters or printed values, review and update the transcription and this comparison explicitly.
